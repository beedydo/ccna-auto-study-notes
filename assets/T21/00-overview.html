AXL
T21.02
 POST https://<cucm>:8443/axl/
Administrative XML: SOAP API for provisioning the config DB. Defined by a WSDL (AXL SQL Toolkit, Application → Plugins). Send to the Publisher.
1header names version + operationSOAPAction: "CUCM:DB ver=14.0 addPhone"
4auth = Basic, application userrole Standard AXL API Access
2body = SOAP envelope, same versionxmlns:ns="http://www.cisco.com/AXL/API/14.0"
5success → 200 addPhoneResponse<return>{uuid}</return>
3verbs: add get list update removeaddPhone getUser listPhone executeSQLQuery
6errors: 401 bad creds · 403 no AXL role500 + soapenv:Fault + axlcode
!Trap: AXL is SOAP, always POST (even for getPhone), Content-Type: text/xml, trailing / on /axl/. A data error is HTTP 500 with a Fault, not a 4xx.

UDS
T21.03
 GET https://<cucm>:8443/cucm-uds/…
User Data Services: REST API with XML responses for end-user and directory data. Built for clients such as Jabber. Any node answers.
1no auth: system info/cucm-uds/version /cucm-uds/servers
4plural = list, singular = one item/users vs /user/{userId}
2directory search/cucm-uds/users?last=Kam
5header Accept: application/xmlXML only, no JSON
3personal data = end user's own Basic auth/cucm-uds/user/jkam/devices → 401 without
6user settings: speed dials, call forward, remote destinationsPUT on the user's own resources
!Trap: UDS is REST but returns XML, not JSON. It is user-scoped, so it can't bulk-add users or phones (POST /cucm-uds/users → 405 in the lab).
