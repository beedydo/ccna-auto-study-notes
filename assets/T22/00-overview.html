T22.01
 4 components = 4 planes
An overlay WAN: IPsec tunnels between edge routers over any transport. Central boxes handle management, control and onboarding. The API keeps the old names in device-type.
!Trap: Controller (vSmart) = OMP + policy. Validator (vBond) = authenticate + orchestrate + NAT, public IP. Don't swap them.
🧑‍💻 your script → HTTPS → SD-WAN Manager only (/dataservice/...)

T22.02
 https://<manager>:8443/dataservice/
One API for the whole fabric, on the Manager. JSON in, JSON out. Swagger docs on the box at /apidocs.
!Trap: login /j_security_check and /logout are at the root, not under /dataservice.
https://manager:8443/dataservice/device/control/connections?deviceId=10.0.0.1
1port: on-prem 8443 · sandbox / cloud 443
3deviceId = the device's system-ip
2blue = API prefix · yellow = resource · green = query
4reply envelope{"header": {...}, "data": [...]} → use ["data"]

SESSION
LOGIN
T22.03 · T22.05
 cookie + X-XSRF-TOKEN
Session-based: login gives a cookie, a 2nd call gives the token. requests.Session() keeps the cookie and the header for every call.
!Trap: 200 ≠ success. Bad password → 200 + error body. Dead session → 200 + HTML login page. Check body / Content-Type.
1Log in
POST /j_security_check
form: j_username j_password
requests data=, not json= → 200, empty body
Set-Cookie: JSESSIONID
2Get token
GET /dataservice/client/token
with the cookie → body is the token (plain text)
session.headers["X-XSRF-TOKEN"]
3Call the API
GET: cookie is enough
POST / PUT / DELETE: cookie + X-XSRF-TOKEN no token on POST → 403
SessionTokenFilter
4Log out
POST /logout?nocache=1 → 302 /welcome.html
frees 1 of 100 sessions (24 h max, 30 min idle)
!Trap: header is X-XSRF-TOKEN, not X-Auth-Token (Catalyst Center, T20). Newer /jwt/login (20.18.1+) uses username/password JSON → Bearer.

T22.04
 /dataservice/<resource>
Inventory and real-time views are GETs. Statistics and alarm queries are POSTs with a filter body, so they need the token too.
!Trap: /template/device lists templates, not devices. Devices = /device.
📋 Inventory · health
GET /device host-name, device-type, system-ip, site-id, reachability
GET /device/monitor status
GET /device/counters control / OMP / BFD
📈 Stats · alarms
POST /statistics/interface
body {"query": {...}, "size": 3}
POST /alarms · GET /alarms/count
real time: /device/bfd/sessions?deviceId=
🧩 Templates
GET /template/device whole-device config
GET /template/feature building blocks
attach: POST /template/device/config/
attachfeature → poll /device/action/status/{id}
