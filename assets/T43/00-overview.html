📝 Register once T43.04

👩‍💻 you are the CLIENT (normal API call)
1POST /v1/webhooks + Bearer token
{"name": "netops room commands",
"targetUrl": "https://…/webhook",
"resource": "messages",
"event": "created",
"filter": "roomId=room-netops",
"secret": "s3cr3t-T43-demo"}
required: name, targetUrl, resource, event; optional: filter, secret
resource = noun (messages rooms memberships); event = verb (created updated deleted)
Trap: the token is needed only to create it. The registration happens once, not per event.

📨 Platform POSTs to you T43.01 · T43.05

☁️ platform is now the CLIENT
3POST https://…/webhook
X-Spark-Signature: 23990cf0… (HMAC-SHA1, 40 hex chars)
{"id": "wh-0001", "resource": "messages",
"event": "created", "actorId": "…",
"data": {"id": "msg-0001",
 "roomId": "room-netops", "personEmail": …}}
// no "text": IDs only
Not 2xx / no reply / refused → retry with backoff → too many fails → webhook disabled
Trap: your targetUrl must be publicly reachable HTTPS. 127.0.0.1 or a private IP never gets a POST.
➜verify

🔐 Receiver: verify + ack T43.03 · T43.05 · T43.06

🖥️ you are now the SERVER
4HMAC over the raw bytes, before json.loads:
hmac.new(SECRET, raw_body, hashlib.sha1).hexdigest() hmac.compare_digest( expected, received or "")
mismatch → 401, ignore payload
seen this data.id? → 200, no second action (retries!)
5new → queue it → 200 OK at once
Trap: slow work before replying → platform times out → retries → duplicate action.
➜queue

⚙️ Worker: fetch + act T43.05 · T43.09

🖥️ you are a CLIENT again
6Follow-up GET with your token:
GET /v1/messages/msg-0001
{"text": "show ip interface brief", …}
7Act: run the command, post the result back
Why a GET? Payload is minimal for security; the platform has no token to read encrypted text for you.
Trap: "the bot gets the message ID but not the text" → it's by design: do the follow-up GET.

🔁 Retries & idempotency T43.05 · T43.06

receiver 500 → retry 0.5 s, 1 s → 200
receiver down → Connection refused ×6 → inactive
reply after 4 s (timeout 3 s) → retry, same data.id
dedupe on data.id → acted once
Trap: delivery is at least once: design for duplicates, not "exactly once".

🎯 Scenario → answer T43.09

1Webhook never fires → targetUrl not public / filter wrong / webhook inactive
2Prove it came from the platform → secret + HMAC (not source IP)
3Same alert handled twice → receiver too slow → ack fast, dedupe
4Need message text → follow-up GET by data.id
Trap: verify on the raw body; re-serialised JSON gives a different HMAC.
