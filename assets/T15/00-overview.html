🔧 OPERATIONS T15.04

<get>running config + state, filter only (no source)
<get-config>config only, from a <source>
<edit-config>change a <target>; nc:operation = merge (default) · replace · create · delete · remove
<copy-config> <delete-config>whole datastore; running can't be deleted
<lock> <unlock>stop other sessions editing
<commit> <discard-changes> <validate>candidate → running · undo candidate · check first
<close-session> <kill-session>end mine (graceful) · force-end another
!Trap: create on existing → data-exists; delete on missing → data-missing; remove on missing → <ok/>

🐍 THE SAFE-CHANGE PATTERN (from netconf_walkthrough.py) T15.05 · T15.08

rpc(f"lock {target}", m.lock, target=target)                     # 1 lock
rpc("merge Gi2 description (default operation)", m.edit_config, target=target,
    config=intf_config("GigabitEthernet2", description="uplink to core"))  # 2 edit candidate
rpc("validate candidate", m.validate, source="candidate")    # 3 check
rpc("commit", m.commit)                                         # 4 now live
rpc(f"unlock {target}", m.unlock, target=target)                 # 5 release
!Trap: order is lock → edit → validate → commit → unlock. Another session's lock → your lock gets lock-denied (+ owner's session-id), your commit gets in-use
