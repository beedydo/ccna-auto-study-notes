📜 XMLparser: ET.fromstring() → ET.ParseError
TWO ROOTS
<a/><b/>
junk after document element
Wrap in one root. NETCONF: <config>…</config>
MIS-NESTED
<a><b></a></b>
mismatched tag
Close in reverse order: <a><b></b></a>
CASE
<Name>Gi1</name>
mismatched tag
Tags are case-sensitive
UNQUOTED ATTRIBUTE
<vlan id=10/>
not well-formed (invalid token)
id="10" or id='10'
RAW & OR <
<d>AT&T 1 < 2</d>
not well-formed (invalid token)
&amp; &lt; &gt; &quot; &apos;
VALID, BUT…
<interfaces xmlns="urn:…">
root.find("interface") → None
Namespace map needed (sheet 05)
VALID
<?xml version="1.0"?><a x="1"><b/><!-- ok --></a>
🧾 JSONparser: json.loads() → json.JSONDecodeError
SINGLE QUOTES
{'name': 'Gi1'}
Expecting property name enclosed in double quotes
That's a Python dict literal. JSON = " only
UNQUOTED KEY
{name: "Gi1"}
Expecting property name enclosed in double quotes
Keys are always strings: "name"
TRAILING COMMA
{"a": 1,} [1, 2,]
Illegal trailing comma before end of object / array
Last item has no comma
PYTHON LITERALS
{"up": True, "mtu": None}
Expecting value
Lowercase: true false null
COMMENT
{"vlan": 10} // users
Extra data
JSON has no comments. Use YAML, or a "_comment" key
LEADING ZERO
{"port": 08}
Expecting ',' delimiter
8, or "08" as a string
PYTHON ACCEPTS, SPEC DOESN'T
{"loss": NaN}
json.loads → {'loss': nan}
Not valid JSON. Other parsers reject it
📝 YAMLparser: yaml.safe_load() → yaml.YAMLError
TAB INDENT
vlans: → - 10
ScannerError: while scanning for the next token
Spaces only, never tabs
INDENT DRIFT
a: b: 1 c: 2
ParserError: while parsing a block mapping
Siblings line up exactly
SECOND COLON
desc: uplink: core
ScannerError: mapping values are not allowed here
Quote it: desc: "uplink: core"
LIST + MAP MIXED
a: - 1 b: 2
ParserError: while parsing a block collection
One level is either - items or key: value
NO SPACE AFTER :
hostname:R1
→ the string 'hostname:R1', not a mapping
hostname: R1
TYPE SURPRISES (YAML 1.1)
enabled: yes mode: on country: NO perm: 010 ver: 3.10 time: 22:30
True · True · False · 8 · 3.1 · 1350
Quote anything that must stay text: ver: "3.10"
VALID (JSON is YAML)
{"a": [1, 2]} # comment ok

🎯 Exam method: check in this order

1Which format? < = XML · {/[ = JSON · key: + indents = YAML
2Structure: one root / brackets balanced / indents line up
3Tokens: quotes, commas, true vs True, escapes, tabs
Trap: the question shows a Python print-out ({'a': True, 'b': None}) and asks if it's JSON. It isn't: single quotes and capitalised literals.
