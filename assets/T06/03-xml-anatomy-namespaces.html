🧬 Namespace = the YANG model's surname T06.02

<config>  <!-- NETCONF wrapper = 1 root -->
  <interfaces xmlns=
   "urn:ietf:params:xml:ns:yang:ietf-interfaces">
    <interface>
      <name>Loopback100</name>
    </interface>
  </interfaces>
  <native xmlns=
   "http://cisco.com/ns/yang/Cisco-IOS-XE-native">
    <hostname>CSR1</hostname>
  </native>
</config>
⇄
{
  "ietf-interfaces:interfaces": {
    "interface": [
      {"name": "Loopback100"}
    ]
  },
  "Cisco-IOS-XE-native:native": {
    "hostname": "CSR1"
  }
}
1XML (NETCONF, RESTCONF +xml): a URI in xmlns="…". It's an ID only; nothing is downloaded.
2JSON (RESTCONF, RFC 7951): the module name + colon on the top-level key, and again wherever the model changes. Children inherit it.
3Same model, two spellings: URI urn:…:ietf-interfaces ⇄ module ietf-interfaces. Two models in one payload → two namespaces, no clash.
Trap: a NETCONF filter with the wrong or missing xmlns returns an empty <data/>, not an error. RESTCONF JSON body without the prefix → device rejects it; reading a reply without it → KeyError.

🧭 XPath = a file path for the XML tree T06.02

/interfaces/interface/ from the root, one level per step: every interface
/interfaces/interface[name="Gi1"]/description[…] predicate = filter: Gi1's description only
//name// = anywhere below: every name element
//mtu/@unit@ selects an attribute
/interfaces/interface[1]position predicate: XPath counts from 1 (Python lists from 0)
<filter type="xpath"
        select="/if:interfaces/interface[name='GigabitEthernet1']"
        xmlns:if="urn:ietf:params:xml:ns:yang:ietf-interfaces"/>
1NETCONF <get-config> filter: type="subtree" (an XML skeleton) or type="xpath" (needs the :xpath capability).
2ElementTree speaks a subset: root.findall(".//if:name", ns), [@unit='bytes'], [tag='text'].
Cousins: RESTCONF URL /restconf/data/ietf-interfaces:interfaces/interface=Gi1 is the same path; the key goes after =, not in […].
