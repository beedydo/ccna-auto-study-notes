🔑 Secrets

T29.01
hardcoded→env / .env (ignored)→vault
1read from env, fail fastrequire_env("LAB_DEVICE_PASS")
2ignore the file.env in .gitignore
3tokens from secrets, not randomsecrets.token_urlsafe(16)
4rotate keys · least privilege per service account
Trap: git rm .env does not remove it from history → revoke + rotate first

🌐 In transit vs at rest

T29.02 · T29.03
script⇄ TLS / SSH / IPsec ⇄API→encrypted disk / DB
1in transit: HTTPS, SSH, NETCONF over SSH, IPsec
2at rest: disk, volume, DB, backup encryption + KMS
3TLS = hybrid: asymmetric handshake → symmetric session key
4sensitive data needs both
Trap: HTTPS does nothing for data once it is stored, logged or committed

📜 PKI + passwords

T29.04 · T29.05
root CAsigns →server cert→verify=True
1cert = public key + identity, signed by a CA
2lab CA: verify=ca_pem → 200
3self-signed / unknown CA → SSLError
4passwords: random salt + slow KDFpbkdf2_sha256$600000$salt$hash
Trap: verify=False still encrypts, but skips identity → MITM

🎯 Pick the secure option

T29.08
1user password → salted slow hash
2API key the script must send → vault / env, encrypted at rest
3file unchanged? → SHA-256 · who sent it? → HMAC / signature
4over the network → TLS / SSH, never Telnet / HTTP
Trap: "encrypt the passwords" is the wrong answer for password storage
