🧭 REST vs RPC vs SOAP: where does the verb live? T09.01 · T09.02 · T09.03 · T09.04 · T09.09

StyleWhat / verb lives inErrors · format · Cisco APIsSpot it on the wire (same lookup: device 1)
🌐REST
T09.01
 Resource-centric style. URI = noun, HTTP method = verb. Many URIs, stateless, cacheable (GET). HTTP status code (404). Any format, mostly JSON.
Meraki · Catalyst Center · Webex · RESTCONF
GET /api/v1/devices/1 Accept: application/json
!Trap: JSON over HTTP ≠ REST. POST /api/runCommand = RPC style
📞RPC
T09.02
 Action-centric. Verb = named function in body/URL. Usually POST to one endpoint.
JSON-RPC · XML-RPC · gRPC (HTTP/2 + protobuf)		 Error in the body, often HTTP 200 (-32601).
NETCONF <rpc> SSH 830 · NX-API JSON-RPC
POST /jsonrpc {"jsonrpc": "2.0", "method": "getDevice", "params": {"id": 1}, "id": 1}
!Trap: 200 OK + "error" = failed. No id = notification, no reply
🧼SOAP
T09.03
 W3C protocol, XML only. Envelope > Header? > Body (> Fault). WSDL = strict contract. WS-Security. 500 + soapenv:Fault in Body.
HTTP POST, SOAPAction header.
CUCM AXL
POST /soap SOAPAction: "GetDevice" <soapenv:Envelope …><soapenv:Body> <GetDevice><id>1</id></GetDevice>
!Trap: Header is optional; Envelope + Body are mandatory; Fault sits inside Body
