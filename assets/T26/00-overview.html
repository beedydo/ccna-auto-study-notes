T26.01
 WHO is the infrastructure for?
NIST names 4 deployment models: private, community, public, hybrid. Multi-cloud is an industry term, not a NIST model.

🏢 Private

one org · on or off premises · most control

☁️ Public

general public · provider's premises · pay-as-you-go

🏛️ Community

orgs with shared concerns (gov, compliance)

🔗 Hybrid

2+ distinct clouds bound together; data/apps move

🌐 Multi-cloud

2+ public providers · avoid lock-in
!Trap: private ≠ on-prem only (can be hosted by a 3rd party). AWS + Azure with no private DC = multi-cloud, not hybrid

 NIST: 5 essential characteristics

1On-demand self-service: no human at the provider
4Rapid elasticity: scale out and in with demand
2Broad network access: any client, standard protocols

T26.08
 monolith vs microservices
One deployable unit vs many small services talking over APIs.

🧱 Monolith

one codebase, one release · simple to start · scale = copy the whole app

🧩 Microservices

own process + API each · deploy/scale one service · fits containers

! Trap

microservices add network calls, distributed debugging and more moving parts; not "always better"
