🧱 Notation T47.01

solid + filled head = request / sync call (method + URL)
dashed = response / return (status + data)
open head = async message (sender doesn't wait)
!Trap: time runs down, not left→right. Boxes = participants; the left-to-right order of boxes means nothing

🔲 Activation + frames T47.02

  • Activation bar (thin box on a lifeline) = that participant is busy
  • alt [guard] / [else] = if/else: exactly one branch runs
  • opt = if with no else · loop = repeat (poll, paginate)
  • par = branches run in parallel · break = exit early
!Trap: alt ≠ both branches. opt = one block that may be skipped. loop = the arrows inside repeat

🔐 Auth flow T47.03

1
Basic creds once
POST /dna/system/api/v1/auth/token
2
200 + {"Token": "tok-0001"}
3
token on every call: X-Auth-Token: tok-0001
4
200 + data · 401 = token missing/expired → re-auth
!Trap: a data call drawn before the token arrow = the bug (→ 401). 403 = token fine, no permission

⏳ Async flow T47.04

1
submit: POST …/cli/read-request
2
202 Accepted + taskId (not done)
3
loop: GET /dna/intent/api/v1/task/{taskId} until endTime
4
result: GET /dna/intent/api/v1/file/{fileId}
!Trap: arrow after 202 = GET the task, not the result and not the POST again (duplicate job)

📣 Webhook flow T47.05

1
register: POST /v1/webhooks + targetUrl
2
event happens → service POSTs to targetUrl
3
app replies 200 fast (2xx or the hook gets disabled)
4
app GETs details: GET /v1/messages/{id}
!Trap: arrow 2 points from the service to the app; the app does not poll. Payload = IDs, not full text
