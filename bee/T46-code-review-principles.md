### T46.01 · Purpose

**Must cover:**

- [ ] Catch defects and security issues early (cheaper to fix)
- [ ] Share knowledge across the team; reduce single points of knowledge
- [ ] Keep code style and standards consistent
- [ ] Mentoring and improving overall code quality

### T46.02 · Process

**Must cover:**

- [ ] Developer works on a branch
- [ ] Opens a pull/merge request with a description
- [ ] CI runs automated tests/linters
- [ ] Reviewers comment; author fixes; approval; merge to main

### T46.03 · Types

**Must cover:**

- [ ] Over-the-shoulder: reviewer at the author's desk
- [ ] Tool-assisted: PRs in GitHub/GitLab (most common)
- [ ] Pair programming: continuous review while coding
- [ ] Email-based: patches sent for review

### T46.04 · Good practice

**Must cover:**

- [ ] Keep changes small and focused
- [ ] Use checklists; review logic, security, tests, readability
- [ ] Constructive, specific feedback about the code, not the person
- [ ] Let linters/formatters and CI handle style
